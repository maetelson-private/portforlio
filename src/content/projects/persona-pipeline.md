## 문제

LLM은 약한 근거로도 그럴듯한 페르소나를 만들어 냅니다. 커뮤니티 데이터는 노이즈가 많고, 중복되고, 출처마다 무게가 다릅니다. Stack Overflow 디버깅 글과 Reddit 불만 글이 같은 고통을 말해도 같은 근거가 아닙니다.

## 접근

- **단계별 파이프라인**: 수집 → 정규화 → 노이즈 필터 → 관련성 필터 → 에피소드 생성 → 규칙/LLM 라벨링 → 축 탐색 → 클러스터링·점수화 → 품질 게이트 → 워크북 출력. 단계마다 다시 돌릴 수 있고, 단계 사이 결과를 파일로 남겨 어디서 무엇이 바뀌었는지 추적합니다.
- **품질 게이트**: 커버리지, 소스 균형, 소스 집중도, 약한 소스 부채, 대표 사례 근거를 각각 검사합니다.
- **주장 경계 분리**: 페르소나의 "주장 가능"과 워크북 전체의 "덱에 쓸 수 있음"을 따로 판정해, 흥미로운 클러스터 하나가 완성된 페르소나 체계로 오인되지 않게 했습니다.

## 결과

- 최종 사용 가능 페르소나 **3개**, 조건부 검토 가능 1개
- 근거가 부족한 클러스터는 승격하지 않고 진단용으로만 남김
- 워크북 전체는 소스 균형 문제가 남아 "검토 가능, 덱 미사용"으로 의도적으로 동결 — 과장하지 않는 것까지가 결과물입니다.
